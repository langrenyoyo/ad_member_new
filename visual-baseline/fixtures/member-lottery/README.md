# 同数据抽奖页对比

使用 `data.json` 中的模拟值，在 1920×1080 视口截取两端 800×600 会员编辑弹窗。对标仅登录、读取、切换页签及填充浏览器表单；未提交业务修改。本地会员读取接口使用模拟响应。脚本从环境变量读取登录凭证，不写入报告。

文件：`reference.png` 对标、`local.png` 本地、`diff.png` 差异标记、`report.json` 像素指标及字段位置。RGB 任意通道相差超过 10 计为差异像素；面积分母包含空白区域，不能当成功能完成率。

已根据对标采集的布局修正：

- 补齐抽奖次数的“次”和倒计时的“分钟”单位。
- 补齐“开启后以当前数据为准”说明。
- 调整页签背景、上方留白、字段纵向间距和标签换行。
- 按参考栅格调整倒计时输入框宽度及分隔符。

修正前差异像素占比为 12.3104%；最新值见 `report.json`。已补齐窗口最小化、最大化、还原及拖动操作。其他像素差异仍待处理，不能声明完全一致。

窗口证据：`reference-window.json` 记录了对标普通、最大化、最小化与还原尺寸。`verify_member_edit_window.py` 使用隔离记录验证本地相同尺寸，以及草稿保留、拖动位置恢复、关闭重开和导航状态清理。参考窗口仅操作标题栏，不提交表单。

字段浏览器回归及编辑生命周期回归通过，包含跨页签修改、仅提交变化字段、保存失败重试和过期请求隔离。本次不验证对标服务端抽奖规则或上线条件。汇总报告还包含此前采集的其他场景，不能视为本轮全部重测。

复现：设置 `PARITY_USERNAME` 和 `PARITY_PASSWORD`，启动本地 3000/8000 服务后运行 `python scripts/compare_member_lottery.py`，再运行 `python scripts/build_fixture_report.py`。
