# 广告后台图片需求实现

已把图片中的运营核检信息接入广告记录列表。新字段用于展示和排查，不能直接改余额或回收奖励。

## 已实现字段

- **回调价**：TAKU 服务端回调 eCPM，优先使用人民币密文解出的价格，否则显示美元价格。
- **客户端价**：APP 上报的 `e_c/e_c_cny` 解密价格，按相同币种与回调价比较。
- **结算价**：当前结算采用的回调 ECPM 数值，保留原有策略结算逻辑。
- **核检标签**：服务端回调与客户端价格差异超过 20% 时记录“回调价与客户端价差异”；缺少服务端 eCPM 证明时记录“缺少 eCPM 回调证明”。历史记录没有证据时显示“正常”，不会猜测标签。
- **诊断结构**：接口同时返回 `diagnostics`，包括价格、币种、关注项数量及 GPS/IP 跨区域状态字段。GPS/IP 需要风控数据源提供后才会标记，当前不伪造结果。

广告列表可以通过列设置显示/隐藏这些列，CSV 导出会带回调价、客户端价、结算价和核检标签。标签用现有安全转义渲染，不把广告标题或标签当 HTML。

## 与图片对应关系

图片中的“改拍价分赚疑×2”“报价偏高·按均价发”“激励秒”“展示/点击/跳转/体验”等是运营展示标签。当前项目已有广告类型、平台、展示时间和 TAKU 交易字段；其中“改报价、按均价发、体验秒”属于业务判定，需要真实的报价变更记录、策略快照和播放时长字段才能准确生成。本次先接入可由现有数据证明的价格对比和缺失证明标签，并为其它风险字段预留结构。

## 数据库与部署

新增迁移 `e936_ad_diagnostics`，为 `ad_records` 增加诊断列。部署时执行：

```text
.venv/bin/alembic upgrade head
```

然后重启后台服务。迁移只增加可空诊断字段，不改变历史余额、奖励流水或提现状态。

## 验证边界

本地已通过 Python 编译、TAKU 对账专项测试和 JavaScript 语法检查。真实回调缺少 `s_id/e_c/e_c_cny` 时仍会按既有规则拒绝发奖；因此线上旧回调记录不会凭空出现回调价。要生成图片中的完整核检标签，需要 TAKU 回调恢复加密字段，并继续采集服务端回调、客户端元数据、播放时长及风控设备关联。
