# 复查问题修复交付

## 已实施

1. 可信 ECPM 预检：保存奖励策略和申请 TAKU 广告时校验本应用 keyring 中 RSA 私钥。没有配置、文件不可读、空密钥集合或密钥损坏时提前失败；重试旧广告也检查原策略快照。普通回调密钥不能替代 ECPM 密钥。
2. Compose 增加 `TAKU_ECPM_KEY_DIR` 的只读挂载和 `TAKU_ECPM_KEYRING_FILE` 透传；后台规则页显示本地密钥检查结果。本地通过不保证广告平台一定发送人民币价格证明。
3. 曝光与结算解耦：24 小时内已结算广告可补报曝光，保持 rewarded 状态，不重复记资金；同事件重复请求返回原结果。审计注明客户端来源、服务端收取时间及是否晚于奖励，不能把补报时间称为真实曝光时间。
4. 标签统计纳入已展示或已结算会话，按结算时间/曝光接收时间排序；已结算但缺曝光的广告也可人工复核。未知仍计入分母。未开启标签奖励时，广告快照跳过标签聚合查询。
5. APP 曝光上报前持久化请求，使用固定事件 ID。初始化和刷新钱包时每轮最多处理 20 条，24 小时过期清理；退出账号清除记录。没有新增后台定时唤醒，只有应用运行时恢复。
6. APP 活动补贴提交前持久化原请求体和幂等键，进入会员中心恢复同一请求；成功清除，明确业务拒绝清除，网络或服务端失败保留。退出账号清除，仍受会话 epoch 保护。普通补贴旧接口和未提交草稿的完整恢复不在此实现中。
7. 增加只读对账模块和脚本：流水等式、相邻流水衔接、余额与末笔流水、无流水期初余额、冻结资金与在途提现、负余额、历史迁移发生截断的字段数量。只报告，不自动调整余额或历史流水。

## 部署配置

把真实平台配套的 keyring JSON 放在受控目录，其格式参见 `docs/taku-ecpm-verification.md`。例如宿主机目录为 `./secrets`、文件为 `taku-keyring.json` 时：

```dotenv
TAKU_ECPM_KEY_DIR=./secrets
TAKU_ECPM_KEYRING_FILE=/run/taku-ecpm/taku-keyring.json
```

不要把客户端 AppKey 当作私钥，也不要将 keyring 放入 APK、公开静态目录或 Git。配置完成后加载业务规则查看检查结果，再用真实广告来源验证人民币证明及结算。缺配置时保存可信奖励策略会返回 503，广告也不准入。

## 对账使用

在备份或生产副本设置 `DATABASE_URL` 后，从项目根目录运行：

```powershell
python scripts/audit_wallet.py --output wallet-audit-before.json
python -m alembic upgrade head
python scripts/audit_wallet.py --output wallet-audit-after.json
```

迁移命令会写入所指定数据库，必须先核对 DATABASE_URL。对账脚本对 PostgreSQL 使用可重复读只读事务；SQLite 使用 query_only。退出码 0 表示未发现差异，2 表示有待核对项。它不是审计证明，导入期初余额和历史排序差异也需要人工解释。报告包含会员 ID 和资金差异，应限制访问。
