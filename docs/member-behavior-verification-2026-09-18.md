# 会员行为弹窗核验

本轮有实际实现和验证进展，整体一比一目标仍未完成。

## 参考证据

`inspect_member_behavior.py` 登录后阻止所有页面业务写入，采集单 APP、多 APP 八个页签的运行时列定义、筛选条件、排序与分页配置。保存在：

- `visual-baseline/reference-verified/member-behavior-tables.json`
- `visual-baseline/reference-verified/behavior-yige.js`
- `visual-baseline/reference-verified/behavior-duoge.js`
- `visual-baseline/reference-verified/member-behavior-scope.json`
- `visual-baseline/reference-verified/member-behavior-device.json`

采集器按每个页签的 href 定位表格，等待该表格初始化；不能通过正在过渡的 `.active` 判断读取对象。范围证据只记录样本数量、键名和相等性判断，不保存账号或设备值。此次非空样本的单/多 APP 记录属于同一个会员，不能据此证明跨账号关联规则。

## 本轮实现

- 将原有八个简化表格接入现有游戏表格控制器，复用筛选、日期范围、排序、页容量/All、跳页、列菜单、卡片视图和六格式导出。
- 单 APP 的表格数据列和筛选项已逐页按参考核验。恢复会员 ID、账号、游戏、内网、白名单、状态、广告字段、金币变动前后、完整地址字段等；日期采用现有北京时间显示，提现金额按参考除以十显示为元。
- 恢复金币类型的文字及颜色；按实际参考 formatter 仅保留 IP、收件人和电话的点击搜索，普通备注不再误显示为链接。
- 分销用户固定使用 `parent_id` 查询，不套用会员管理的编辑/批量启停操作。提现页复用现有单笔、批量审核控制器。
- 每个页签保留独立的筛选、页码、排序、列和卡片状态；切换页签中止旧读取并隐藏日期选择器。关闭父弹窗或切换路由会销毁全部控制器和日期绑定。导出携带相同的固定会员/游戏范围。
- 风控列表原 `user_id` 为模糊筛选。增加精确 `member_id` 条件用于行为明细，原列表模糊筛选保持可用；已验证 123 不会匹配到 9123。
- 每日收益补上账号、收益/日期排序、日期范围校验；地址接口补上现有存储内容的精确字段与日期筛选。
- 金币接口返回所选会员的累计收益、可用金币和冻结金币。仅在会员与指定游戏相符时返回，独立于筛选后的金币变动合计。前端恢复三个金额面板及工具栏合计。
- 行高恢复为参考的 47px。手机上金额面板分行、表格可切换卡片，无容器横向溢出。
- 恢复抽奖顶部的金币与点击计数面板、双列设备信息。计数列间距、面板尺寸与参考对照；未知设备信息和点击数留空，不用广告或抽奖条数冒充点击数。
- 新增 `MemberDevice` 与 `MemberAppUsage` 存储。抽奖汇总独立于表格筛选，当前按北京时间当天成功抽奖记录计算金币总额与均值；当天点击数只显示 `counter_date` 为今天的已存储计数。
- 新增 `PATCH /members/{id}/device-ban`，分别保存设备 ID 和 IMEI 的封禁状态。operator/risk 可操作，reviewer 不可操作；缺少标识返回 422，标识已变化返回 409，状态变化时写入操作记录，重复相同状态不重复记审计。此接口只实现后台状态管理，不代表游戏端拦截已经接入。
- 按钮保存期间锁定两个目标；保存成功先采用返回状态，再刷新列表，刷新失败不会把按钮恢复成旧状态。缺少设备标识禁用对应操作；关闭父弹窗后的保存响应不再刷新页面。
- 新增 `GET /members/{id}/app-usage`，按会员及可选游戏读取持久化的六列使用记录。前端每批最多 200 条，校验总数与重复 ID；权限错误或数据变化时提示重试，不展示不完整结果。
- APP 详情按参考实际弹窗恢复 800×600、45px 深色标题栏、白色内容区、左对齐表头与条纹表格。标题为“APP应用”，支持拖动、最小化、最大化、还原、Escape、父弹窗关闭及路由清理。最小化后父窗口可操作，详情数据保留。手机端表格可横向滚动。
- 多 APP 行为页按参考动态定义补上会员 ID、游戏名筛选；固定行为范围参数与用户输入筛选取交集，游戏名称包含 `%`、`_` 时按字面匹配。登陆历史/收货地址的游戏名使用精确匹配，其它行为记录使用字面包含匹配；单 APP 页不显示这些额外筛选。
- 按参考恢复多 APP 的会员 ID/游戏名点击搜索，地址收件人/电话保持普通文本；分销游戏名称新增独立包含参数，原会员管理的精确 `game_name` 契约不变。多 APP 会员筛选默认显示当前 ID，首次请求与显示一致，重置后仍保留不可变的会员范围。
- 多 APP 抽奖设备面板按参考不展示 IMEI 与 SIM 行。行为筛选区按参考恢复列宽、33px 输入框、15px 行距、正常字重和绿色提交按钮，按钮紧随最后一个字段排列；移动端折为单列。
- 修复每日收益将不同游戏同日流水合并并错误标成会员当前游戏的问题。现在按实际 CoinLog 的游戏和北京时间日期分组，日期/游戏筛选在聚合前执行，排序在分页前执行。分组 ID 使用该组最小流水 ID，筛选或排序不会重编号。仍是净金币变动聚合，不等同于已证明参考收益口径。
- 修复会员行为提现汇总包含其它会员金额的问题，固定 `user_id` 范围现同时约束汇总。汇总仍独立于列表的临时筛选。
- 新增迁移 `e920_member_devices`。会员删除关联检查包含设备状态和 APP 使用记录，游戏删除关联检查包含 APP 使用记录，避免留下孤立数据。

## 验证结果

- `python -m unittest discover -s backend/tests -v`：62 项通过。新增专项覆盖所有多 APP 读取接口的交集筛选、字面包含/精确匹配区别、分销父级范围、汇总范围、跨游戏每日分组、北京时间边界、稳定分组 ID、排序分页与日期极值。
- 后端新增专项覆盖北京时间跨日边界、失败抽奖排除、会员/游戏隔离、点击日期过期、两个封禁目标独立性、权限、标识冲突、重复操作审计、无标识验证、设备号回退、APP 使用分页排序与删除关联检查。测试数据库均为隔离的临时 SQLite。
- `verify_member_device_migration.py`：空库升级到前版再升级 head、字段默认值/可空性/索引、重复升级、仅回退新增表、重新升级与数据库完整性检查通过；不操作业务数据库。
- `verify_member_device_browser.py`：六项计数、设备字段转义、独立封禁、重复点击锁定、403/409、保存后刷新失败、刷新后设备标识缺失、203 条 APP 记录分批读取、六列与日期、重复/变化批次、空态与错误重试、窗口拖动/最小化/最大化/还原、390px 布局、关闭后迟到读取/写入与路由清理通过。所有业务写入均由内存 fixture 拦截。
- `verify_member_behavior_multi.py`：多 APP 八个页签的参考列/筛选/搜索链接、固定范围与输入筛选交集、筛选保留/重置、导出、移动端及单 APP 隔离通过。参考固定数据截图的筛选展开状态也已重新对照。
- `verify_member_behavior_browser.py`：按参考逐页检查单 APP 数据列和筛选字段；范围、颜色/金额、日期参数、跨页签状态、排序分页、JSON 导出、403 后保留数据/重试、手机布局与清理通过。业务请求均拦截到内存 fixture，无实际业务写入。
- `verify_behavior_contract.py`：旧响应不能覆盖当前页、分销范围、金币类型未误限定、页码保留、父弹窗关闭及路由离开取消请求通过。
- `verify_game_member_switches.py`、`verify_game_userdata_browser.py`、`verify_game_pagination.py`、`verify_game_withdrawals_browser.py` 回归通过。
- `npm run check`：34 个 JavaScript 文件通过。
- 运行中的 8000 后端 OpenAPI 已出现精确 `member_id`、设备状态和 APP 使用记录接口，确认服务加载了更新。

## 尚未完成

- 顶部面板与设备操作入口已恢复，但参考站抽奖金币均值和点击计数的实际统计定义尚未证明与当前计算一致。
- 设备元数据、点击计数与 APP 使用记录尚无实时上报/同步接入；新增存储和查询只支持已有持久化数据，不生成虚构使用记录。APP 使用时间当前以秒显示，参考站有数据时的时长格式、日统计归并规则仍需核实。
- 设备/IMEI 封禁目前按会员保存后台状态，尚未接入游戏登录/抽奖拦截，也未建立相同设备标识跨会员的全局封禁规则。设备更换与会员档案设备字段的同步仍待数据接入时明确。
- 多 APP 的额外筛选已恢复，但跨 APP 身份关联规则仍未确定。当前按固定会员 ID 跨游戏读取，不能宣称与参考站的跨账号关联一致；当前只读样本不足以证明该规则。
- 每日收益已修复跨游戏混组，仍基于现有 CoinLog 按北京时间聚合；参考 `coinday` 的持久化收益口径未证明与净变动一致，聚合分组 ID 也不是参考独立日收益记录 ID。
- 地址仍是现有会员档案地址接口，不是真正多记录地址簿；电话、邮箱编号没有持久化来源时不生成虚构值。完整地址簿功能尚未完成。
- 行为提现仍缺参考编辑入口及部分工具栏/操作列位置一致性；其它页签的顶部汇总和整页像素对照还需推进。
- 工具栏图标、部分字体/间距和菜单样式仍有差异。
