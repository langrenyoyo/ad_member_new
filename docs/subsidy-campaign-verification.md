# 补贴活动实现与验证

截图对应功能已加入后台补贴页面：活动配置、按北京时间统计名额、提现门槛、三类凭证、审核时限提示。APP 提交后共用原有补贴审核记录。

数据模型新增 `subsidy_campaigns` 和 `subsidy_reservations`，迁移为 `e926_subsidy_campaigns`。开发环境启动自动建缺失表；正式环境需执行 Alembic 迁移。现有补贴记录不改写；未配置活动的游戏保留原接口。

默认新建值来自截图：50 名、提现 5 元、充值 6 元补贴 12 元、24 小时审核。新建默认关闭，不自动创建或开放实际活动。

资格和名额检查、补贴记录和配额记录在同一事务提交；请求编号提供幂等重试。每天每用户每活动一次，驳回和删除均不退还名额。活动配置修改不能改写已提交规则快照。

验证入口：

- `python -m unittest backend.tests.test_app_subsidies -v`：基础链路、名额并发、请求重试、删除后配额保留、北京时间边界、权限、凭证校验、规则快照与审核结果。
- `python scripts/verify_subsidy_campaign_ui.py`：隔离数据库和 HTTP 服务，真实浏览器创建、编辑活动，刷新后核对数据及浏览器错误。
- `python -m unittest discover -s backend/tests -v`：后端回归。
- `npm run check`：前端语法检查。

限制：现有支付适配器未接通实际渠道；审核通过不表示已打款。提现资格以已确认转账记录计算，现有模型不能单独区分广告来源。充值真实性、安装来源、保留应用由审核人员核验，尚无第三方自动验证。审核超时提供页面提示，尚无外部通知任务。本轮范围为补贴页面，邀请、返佣、VIP、排行榜、公告等其他截图功能未在本轮实现。
