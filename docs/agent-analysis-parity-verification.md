# 主体数据分析核验（2026-09-18）

已移除误用统计页数据的六张汇总卡片、日表格和无依据的地域多边形。页面现按参考 `agents/assay/index/agent_id/{id}` 展示四张饼图、APP 来源条形图、总金币/平均金币散点图与会员明细表。本轮不证明全站或所有分析业务口径已一致。

## 参考证据

`inspect_agent_analysis.py` 登录后限制浏览器 GET/HEAD，屏蔽危险路径；凭据通过已有脚本 AST 提取而非写入新文件。参考接口响应只记录字段形状及聚合值，设备、IP、账号和密钥值不进入报告。分组表单只追加合成行用于截图，没有向参考发送保存请求。

当前参考主体的只读样本：42 次抽奖合计 20.23，42 次成功；散点为 `[20.23, 0.48]`，公网记录数 42。`coin_every=0.48,0.48`、`coin_user_total=20.23,20.23`、`success_percent=100,100`、`app_num=1,1` 均命中该会员，支持两位小数及包含边界的本地实现。参考单边高值范围探测返回 500，本地支持单边查询，不复制该错误。

控制器证实：默认排序 `user.id desc`，四组数值区间和抽奖日期；会员金币/冻结金币/创建时间排序；无列选择、导出、卡片或顶部刷新按钮。表中操作为会员白名单/状态开关、单/多 APP 行为、修改金币和编辑。四饼图依次为金币、成功率、网络环境、APP 数量；网络环境按钮无弹窗，其余三项打开分组表单。

分组表单字段为名称、开始(>=)、结束(<=)，支持追加、删除和拖动排序。窗口 800×600、无遮罩，标题与入口名称一致，有最小化/最大化/关闭。

## 本地实现

- 新增 `GET /agents/{id}/analysis`。从主体下会员和主体下游戏的真实 LotteryRecord 聚合，抽奖日期先过滤，数值区间在聚合后过滤，最后排序/分页；图表基于完整过滤结果，不基于当前页。记录不足或不存在时不生成虚构抽奖。
- 返回有限的会员明细字段，累计/本月/今日/可用/冻结金币来自会员字段；分析总金币、平均金币、成功率、APP 数量来自抽奖聚合。网络图计数为明确的 network_status=0/1，未知不强行归类。
- 共享表格提供页码、首尾循环、跳页和 All 分批；前端校验数字、上下限和日期。页面/主体切换清理旧响应与 ECharts 实例，ResizeObserver 更新六图尺寸。小于 300px 的饼图将标签放入图内，避免窄屏裁切。
- `GET/PATCH /agents/{id}/analysis-settings` 保存独立的 coin/success/apps 分组。PATCH 仅合并提交的分组，避免不同弹窗覆盖其他分组；operator/superadmin 可写。空名称、非有限值、负范围、倒序和重叠范围返回 422。GET 不创建配置记录。
- 新表 `agent_analysis_config` 及迁移 `e923_agent_analysis`，父版本 `e922_admin_avatar`。配置删除随主体删除，不阻止无业务依赖主体的删除。
- OSS 与配置使用同一 `createAgentWindow`，支持拖动、多窗口、最小化停靠、最大化、还原及最上层 Esc；配置支持追加、删除、拖动/键盘排序、重置、保存错误重试、重复提交锁和路由清理。

## 尚未证明

参考样本只有单会员、单 APP，不能证明跨 APP 归并身份及所有游戏来源排序规则。本地 APP 数量按同一会员在当前主体抽奖记录中的 distinct game_id 计算，完整参考语义待多 APP 数据或源代码核对。

参考分组当前为空，未向其保存自定义分组。本地金币分组使用分析总金币、范围包含两端且拒绝重叠；参考配置的分桶指标、重叠优先级、异常/失败奖励计入规则与配置权限仍未充分证明。参考表格顶层白名单/状态字段与嵌套 user 字段的差异也需多状态样本核实；本地操作与显示使用持久化会员状态。

目前端到端行为和真实本地读取可用，但以上业务口径缺口、会员编辑完整参考约束及现有开发库历史迁移漂移仍阻止全站一比一和正式上线结论。
