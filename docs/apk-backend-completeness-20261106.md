# 邀请码版 APK 与当前后台差异复核（2026-11-06）

## 结论

主要会员、广告、钱包、邀请码及补贴功能在当前后台都能找到对应接口或管理入口，但发布 APK 并非当前 Android 工作区版本；补贴活动分页存在可复现的客户端缺陷，独立补贴公告和补贴审核后的资金到账闭环仍未实现。不能仅凭接口和本地测试认定线上整体验收完成。

## 核查对象与边界

- APK：`鸭只易记-v1.0-release-邀请码版-20261104-222625.apk`；包名 `com.heshangzhilian.yazhiyiji`，versionName `1.0`，versionCode `1`。
- APK SHA256：`890CDD495807A51BC8439916D77165919113A0E875B24EAF14780AFC6748A40D`。
- APK 的 `version-control-info.textproto` 指向 Android 源码提交 `458b991f371eb23082de4e8bc29b47f1f1e6c98f`。该提交的成员中心分页请求与现有工作区不同；工作区三个未提交 Android 文件不应当作 APK 已包含的代码。
- APK 配置的 API 根地址为 `https://admember.yunjizhilian.asia/api/app/v1/`，注册游戏 ID 为 `238`。
- 本次基于 APK 反汇编、构建提交源码、当前后端和管理端源码，以及隔离测试。没有登录生产账号、查询生产数据库、执行服务器迁移、真机验收或真实提现/补贴付款。

## 本次发现的具体差异

### 1. 补贴活动“加载更多”实际重复请求第一页

成员中心列表组件根据响应里的 `total` 显示加载更多按钮，并在点击时计算下一页偏移；但 APK 的活动请求仍为 `subsidy-campaigns?game_id=...`，没有带上 `limit/offset` 或 `page/page_size`。当前服务端默认每页 20 条，并返回分页元数据。因此，活动总数超过 20 时，APP 点击加载更多会再次收到第一页，继续满足 `hasMore`，产生重复活动而无法翻到后续记录。

同一 APK 对申请记录、金币、分佣、团队、提现和广告记录会传 `limit/offset`；当前后台兼容这套旧参数，故其与新版 `page/page_size` 参数的差异目前有兼容，不是 API 中断。活动请求漏传分页参数则是独立问题。当前 Android 工作区已经改成 `page/page_size`，但这项修改没有进入本次 APK 所对应的构建提交。

### 2. 强制邀请码开关与 APK 文案不完全一致

APK 注册输入框将上级邀请码提示为“新用户必填”。当前后台按游戏提供 `require_registration_invite` 开关；开启时要求有效的六位英数字团长/代理邀请码，关闭时允许不填。因而关闭开关后，服务端行为正确，但 APK 文案仍会让用户误以为必填。当前 Android 工作区已换成说明“是否必填由应用注册规则决定”的文案，但 APK 仍是旧字样。

普通会员邀请码的后端生成和展示接口已存在；APK 首页展示 onboarding 返回的邀请码，因此无需 `/invite-code` 独立请求也可在首页看到邀请码。APK 没有独立的邀请码管理或分享页面证据。

### 3. “补贴公告”目前由两类内容拼成，不是一个公告模块

- 首页公告由“设备风控 → APP 业务规则”按游戏配置并下发。APK 登录后展示非空公告；前台运行时约每 60 秒刷新一次。该公告可以写补贴通知，但没有公告列表/历史、定时生效/过期、已读状态或强制确认。
- 补贴活动的 `instructions` 由“补贴申请 → 补贴活动与每日名额”管理，APP 在活动详情展示领取说明、金额和条件。
- 两份内容是独立配置；改公告正文不会改变补贴金额、资格或审核规则。未发现独立“补贴公告中心”。

若验收标准是“有一段公告能在首页展示”或“活动详情有领取说明”，已有基础实现；若标准是可追踪、可读回执、可定时发布的专属补贴公告模块，则尚有差距。

### 4. 审核通过没有资金结算

APP 和后台的申请、截图、资格判断、每日名额、幂等重试、审核结果查询都有实现。审核接口只更新 `status`、审核时间和说明；测试也确认会员金币余额不变且不会创建金币流水。补贴审核通过不会自动转支付宝款，也不会自动给金币。

如果业务承诺“审核通过即到账”，后台还需补贴付款记录/支付请求、幂等键、支付回执查询、失败重试或人工补偿、对账，以及 APP 可展示的实际到账状态。现有审核时限只用于记录审核截止与超时提示，不是自动审核或付款任务。

## 发布与运行风险

- 活动表和每日名额预留表需要迁移 `e926_subsidy_campaigns` 创建；本次没有访问生产服务器确认迁移状态。
- APK manifest 允许应用使用明文 HTTP 流量（`usesCleartextTraffic=true`），尽管业务 API 根地址配置为 HTTPS。建议发布构建收紧明文流量策略，并检查广告 SDK 的必要例外。
- 本地答题进度未发现云同步；如果用户预期换设备后恢复答题记录，当前 APP 与后台能力不匹配。
- 社交登录、广告奖励、设备风控、生产出款等第三方链路须以生产密钥、渠道回调和真实设备验证，源码存在不等于生产服务可用。
