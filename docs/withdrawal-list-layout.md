# 提现列表：同数据布局修正

`compare_withdrawals_fixture.py` 使用三条相同虚构提现数据，覆盖申请中、通过、失败以及零值和较大金额。两端筛选区折叠；只在浏览器内注入数据，不提交对标业务操作。

实测本地单元格为 13px 字体、12px 上下内边距；对标为 14px 字体、8px 上下/15px 左右内边距。已修正字体、内边距、表头行高和外边框，并将排序箭头独立定位，避免撑宽文本。

修正后：

- 两端表头均为 41px，数据行均为 47px，三条数据的表格总高均为 183px。
- 扣除侧栏 230px、顶栏 50px 后，表格、首行及工具栏位置一致；工具栏高度均为 54px。
- 默认可见 20 列中，隐藏字段现在按对标从首屏 DOM 布局中移除；用户行为列本地 103.015625px / 对标 120px，审核操作列本地 181px / 对标 93.1875px，尚未对齐，因此整表宽度仍不同。表格首行 HTML 采集显示对标当前申请行操作为“拉黑”及编辑图标，本地为审核动作按钮；这属于权限/操作语义差异，不能用 CSS 伪装成一致。
- 当前差异像素占比从 6.3506% 降至 4.3166%；不能换算为完成率。

重新采集确认隐藏列已不参与布局，表格仍因两列操作内容的最小宽度而比对标更宽。`inspect_withdrawal_actions.py` 在当前对标账号无数据时得到空操作列，未尝试制造或提交操作；固定夹具中已观察到对标申请行的“拉黑”与编辑图标。

脚本记录表头、子节点和首行单元格计算样式，新增上述已对齐位置、行高和列宽断言。浏览器审核回归及批量确认范围回归通过。该修改未更改真实支付逻辑；实际支付渠道、审核操作可见性和权限差异仍需核验，卡片视图未做双端视觉验收。
