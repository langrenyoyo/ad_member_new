# 业务端 APP 联调测试流程

版本：2026-10-28  
适用范围：鸭只易记 Android APP、用户 APP API、管理后台核验页  
用途：按业务顺序验证登录、广告与发奖、会员/分佣、补贴、提现、风控和收益核检。

## 1. 测试原则与环境

### 环境边界

| 环境 | 用途 | 允许操作 |
| --- | --- | --- |
| 本地/隔离环境 | 功能、接口、异常和模拟支付回归 | 使用临时数据库和模拟广告/支付提供者；只代表隔离测试 |
| 预发布环境 | 真机联调及外部服务沙箱测试 | 使用专用测试账号、测试游戏、平台测试广告位和支付沙箱 |
| 生产环境 | 只读健康检查、经授权的低风险核验 | 不注册测试用户、不产生真实广告奖励、不提交补贴/提现、不发起转账；写入测试另行授权 |

本流程默认使用预发布环境。不得将真实收款账号、生产凭据写入报告或截图。支付渠道为未配置时只验证安全拒绝，不尝试绕过禁用状态。支付宝沙箱与生产环境订单不可互相查询或重试。

### 开始前准备

由测试负责人准备并记录以下信息；缺少外部依赖时，将对应项标记“阻塞/未测”，不要用模拟结果代替：

1. 一台安装指定测试 APK 的 Android 真机；记录型号、系统版本、包名、APK 版本和 SHA256。
2. 一个启用的预发布游戏，配置有效广告位和测试广告流量；该游戏必须与测试账号绑定。
3. 至少一个已登录测试会员；如测邀请/分佣，另准备普通用户、团长、代理及可用邀请码各一组。
4. 对短信、微信、TAKU、阿里云风控和支付宝沙箱分别确认测试凭据、产品权限和回调配置。只检查“配置存在”不算服务可用。
5. 测试前记录会员可用金币、冻结金币、金币流水条数、广告历史条数、提现/补贴记录条数，以及游戏奖励/风控配置快照。
6. 预先约定测试数据清理范围。优先使用独立预发布库和测试账号；不得用整库回滚清理持续运行环境中的单批数据。

## 2. 执行总流程

每个用例按“初始状态 → APP 操作 → 服务端/后台核对 → 记录证据 → 恢复数据”执行。每次只改一个业务条件。出现资金、账号归属、平台订单号或状态异常时，先停止后续写操作，保存 request ID、业务 ID 和时间供排查。

### A. 启动、登录与账号归属

| 用例 | 操作 | 预期与核对 | 结果 |
| --- | --- | --- | --- |
| A1 启动与恢复 | 冷启动 APP；等待初始化完成；退出后台再恢复 | 首页/个人页正常；无登录态账号进入登录页；已登录测试账号显示正确会员与游戏 | □通过 □失败 □未测 |
| A2 登录 | 使用授权测试账号按已启用方式登录 | 服务端建立用户会话；APP 会员资料、钱包和游戏归属一致；错误密码不建立会话 | □通过 □失败 □未测 |
| A3 会话恢复/退出 | 登录后重启 APP；再退出登录并访问会员页/钱包 | 有效会话可恢复；退出后需重新登录；不得用旧响应覆盖新账号状态 | □通过 □失败 □未测 |
| A4 接口权限 | 分别以用户 token 请求本人和他人资料；尝试用管理员 token 请求 APP 接口 | 用户只能读取本人数据；越权被拒绝/返回 404；管理员 token 不得代替 APP 用户 token | □通过 □失败 □未测 |

注册测试另需启用可用注册渠道。验证新用户绑定团长/代理邀请码成功、普通用户邀请码被拒；失败注册不得留下半绑定记录。短信未配置时不发送真实短信，也不以验证码页面可打开判定短信接入通过。微信须使用已登记的真实测试应用授权，不使用伪造 code。

### B. 首页广告组与激励发奖

在预发布测试广告位执行，开启屏幕录像并记录每一步的北京时间。广告组展示和服务端发奖是两个独立验收点。

1. 登录测试会员，记录钱包余额及金币流水数量。
2. 点击“获取更多金币”一次，观察首个插屏；关闭后等待激励视频出现。
3. 完成激励视频规定内容，等待激励关闭；观察末尾插屏并关闭。
4. 等待 APP 流程完成/冷却，进入广告历史页和钱包页刷新结果。
5. 后台按同一会员、游戏、广告会话和时间核对广告会话、平台事件、金币流水及钱包余额。

**通过标准：**广告顺序严格为“插屏 → 激励视频 → 插屏”；每个广告关闭后才启动下一个；一组仅发起一次激励会话；没有额外全屏广告；只有服务端验证成功后出现一笔奖励流水，余额变化与流水一致。重复完成事件、重复平台回调不能重复入账。

另执行负向用例：激励未完成/主动退出、广告无填充、加载超时、关闭页面或切换账号。未通过服务端验证时不得增加金币；失败和取消应有明确状态；迟到回调不能奖励到另一个账号。

**eCPM 核验分开记录：**记录 SDK/平台原始证明是否存在、验签与解密结果、广告会话绑定、平台交易去重，以及 s_id / e_c / e_c_cny 的真实取值状态。不能把 S2S HTTP 200、客户端上报或 reward_amount 单独当作可信 eCPM 证明。S2S 单笔证明和 D+1/D+2 报表核检是两套流程，分别验收。

### C. 补贴入口与申请

1. 在会员中心进入“补贴活动”，记录入口是否请求/展示插屏；关闭广告后确认是否仍在会员中心并进入正确活动页。
2. 打开活动详情，核对资格、名额和规则；满足条件后上传规定凭证并提交一次申请。
3. 进入“补贴申请记录”，核对本人记录、凭证、申请状态和详情；读取其他会员记录应被拒绝。
4. 管理后台审核通过或驳回；回到 APP 刷新，核对同一条记录状态及审核备注。
5. 分别验证重复提交、超名额、不符合资格和图片超限时的幂等与拒绝行为。

**通过标准：**插屏关闭后进入目标页面；申请人与凭证归属正确；重复操作不产生重复申请或重复占用名额；审核结果回读一致。活动审核通过**不代表已打款**，也不应自动变更钱包或提现到账状态。

当前真机已有“补贴插屏展示，但关闭后回到个人页并显示未登录”的失败记录，因此该用例在问题修复并复测前必须标记失败，不得仅凭插屏出现判通过。

### D. 钱包、支付宝绑定与提现

先读取支付状态和游戏档位。支付渠道不可用时只执行安全门禁用例：

1. APP 钱包显示可用金币、冻结金币、支付宝绑定状态、提现档位和支付可用状态。
2. 当 payment_available=false 时，提现按钮应禁用并显示服务不可用；不得创建提现申请或冻结金币。
3. 在隔离 API 用例中对 POST /api/app/v1/withdrawals 验证不可用渠道返回 503，提现记录、余额和冻结额不变。

只有预发布支付宝**沙箱**已配置且取得测试许可后，才继续：

4. 使用专用沙箱收款账号绑定；用正确密码成功、错误密码被拒；确认接口只返回脱敏收款资料。
5. 选择服务端提供的合法档位提交申请；确认可用金币减少、冻结金币增加，记录为待审核；幂等重试返回同一订单。
6. 管理后台审核通过后，通过沙箱转账接口发送；分别验证成功、明确失败、超时待确认、主动查单、重复通知和原商户订单号重试。
7. 只有渠道签名确认成功才清除冻结额并标记到账；明确失败/驳回只退款一次；结果不确定时继续冻结且不得重复付款。
8. 检查 APP 提现记录、管理后台、payout 状态和金币流水三方一致；只有 payout.state=succeeded 才判定到账。

禁止在生产环境用本流程发起真实小额打款。真实生产支付需要单独批准、目标支付宝应用权限、风险评估、财务核对及回滚/补偿安排。当前后台仍有已审核未打款订单缺少取消解冻通路、状态筛选不一致和支付详情展示不足等已知问题，详见[提现管理核查](./withdrawal-management-audit-20261028.md)。

### E. 会员等级、邀请码与分佣

准备用户、团长、代理及至少两级下级的测试关系，记录预期比例和每笔广告业务 ID。

1. 以团长/代理邀请码注册新账号，核对 parent/member/游戏归属；普通用户邀请码应被拒。
2. 对测试广告完成一次有效奖励，核对符合规则的每一级受益人及比例、佣金流水、来源会话和钱包变化。
3. 重放相同平台交易/奖励事件，确认奖励和分佣均不重复。
4. 查询团队、佣金记录、钱包和金币流水，核对金额与比例；比例变更后历史会话仍按创建时快照，不被追溯重算。

未经业务负责人确认的比例不得自行填入生产；比例为零或功能开关关闭时，不得把页面显示等级/团队当作分佣已启用。

### F. 白名单、eCPM 与风控

仅在隔离或预发布环境执行。先保存规则配置快照，再逐项测试，完成后恢复原值。

1. 验证白名单独立最低/最高金币区间、区间合并、广告申请时快照和限次；白名单只豁免指定风控，不豁免登录、账号状态、会话签名、重复交易和奖励证明校验。
2. 使用可核对的人民币 eCPM 样例覆盖不同档位，核对试算奖励、上限、倍率及金币精度；无可信价格、币种不符或证明无效时不得按伪造金额发奖。
3. 通过真实测试设备挑战验证设备绑定、频次、冷却和解除；模拟风控记录只能检查后台字段显示，不能证明阿里云设备识别有效。
4. 后台核对风险会员/广告记录中的核检率、差异额、币种、人工复核广告类别和“疑似双清”标识。未知数据必须保持未知，不能显示为 0 或正常。

当前生产游戏仍有风控/奖励配置未启用项；设备服务外部权限及真实 token 需要单独验收，未完成前保持生产规则关闭。

### G. TAKU 次日收益核检

1. 确认对应应用、广告位、日期和币种的 TAKU D+1/D+2 报表已获取并导入；仅定时器 success 不算报表导入成功。
2. 核对报表批次和明细完整性、用户/广告位映射、自然日时区、展示数及币种。
3. 在后台提现/风控视图选择同一用户和完整自然日范围，核对 TAKU 收益、后台展示预估、差异额、差异率及颜色分类。
4. 缺报表、缺广告位、用户不唯一或混币种时，结果应显示待核验/未知，不得把差异判成 0。
5. 保留导入批次 ID、报表日期、筛选条件和页面截图。S2S s_id/e_c/e_c_cny 不能替代 D+1/D+2 报表金额。

当前最近一次只读检查游戏 238 报表批次数为 0，此项应标记“阻塞/未测”，待取得真实报表后再验收。

### H. 会员、广告历史与后台结果复核

完成前述用例后，按会员 ID、游戏 ID、时间范围核对：

- APP 会员资料与服务端会员绑定一致；用户只能看到自己的数据。
- 钱包可用/冻结金币等于初始值加上对应流水；奖励、退款、冻结、提现结算均有唯一来源 ID 和业务记录。
- APP 广告历史与服务端广告会话、平台回调和金币流水一致；插屏展示不能冒充激励会话或奖励记录。
- 后台广告名称/类别若来自人工复核，应标记复核来源；不得把推测当成自动识别结果。
- 补贴审核、提现审核、支付到账和广告收益核检状态分别显示，不可互相代替。

## 4. 总体验收条件

全部适用用例通过且证据可按账号、会话、交易和流水关联后，才能对相应业务范围标记“验收通过”。任何一项未配置或未取得真实平台数据应标“阻塞/未测”；已复现缺陷应标“失败”。模拟广告、模拟回调、模拟数据库、预览提现行和 HTTP 200 只代表各自范围内的证据，不能升级为真实发奖、真实收益核减或真实打款通过。

生产上线验收还需修复已知 TAKU eCPM 回调分支问题；取得真实可用日报并完成核检；完成数据库备份/迁移/恢复演练；完成授权的外部短信、微信、风控和支付验收；处理或接受提现未发送订单取消解冻及状态展示问题；完成生产权限、日志、备份、告警与回滚检查。
