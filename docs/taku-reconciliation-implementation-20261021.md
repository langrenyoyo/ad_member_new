# 次日收益核对实现（2026-10-21）

本次为本地实现，未修改线上数据库、未部署或启用服务器定时任务。

## 使用入口

后台「广告联盟设置」新增「TAKU 用户收益核对」。超级管理员选择游戏、日期（UTC+8）、可选会员 ID，可查询结果、设置阈值、导入设备明细 CSV 或从 TAKU 同步所选日期。

默认基准是后台 SDK 展示预估。按用户、广告位、币种聚合所有广告平台，用 impressed_at 的北京时间自然日与设备报表对齐，只计 shown 元数据一次。展示次数不一致、缺少已解密 SDK 价格时不标记；当前横幅、原生等无本地完整收益采集时不能承诺全广告类型对账。也可选 TAKU 报表预估基准，此时使用相同币种的 estimate_revenue/cny_estimate_revenue。界面须区分这两种基准。

默认超过 20% 且预估金额至少 0.01、展示至少 3 次才标记。金额门槛单位为当前报表币种；不自动换汇。每个用户/广告位/币种独立判定，异常会员为至少一个范围被标记的会员集合，不代表合并全部币种后的整体差异率。

标签仅表示疑似收益差异。平台 revenue 属于设备分摊收益，D+2 也不是最终结算账单。初步报表与补齐后复核分别标记。标记不会修改钱包、提现权限、分佣或封禁状态。

## 数据与保护

- CSV 需包含 user_id、placement_id、network_firm_id、impression、revenue、currency；缺少同币种预估时 TAKU 基准不可比较。
- 不要求 adsource_id：官方设备报表按广告平台提供 network_firm_id，不能把未提供的字段当作必填。
- User ID 只匹配本游戏会员。没有 user_id 暂不自动回退 OAID，避免误关联；本批次同设备出现多个账号则待人工核对。
- 不保存原始 OAID/Android ID，仅在导入时对设备标识哈希用于歧义检测。
- 上传文件须由管理员确认应用、日期、时区及全量性。CSV 不一定自带这些信息，系统无法替代该确认。
- 版本化保存导入聚合数据和导入管理员；修改阈值写审计。查询按当前规则重算，不宣称历史规则已自动回放。
- 重复导入同一最新文件幂等；修订版本完整替换查询视图但保留旧批次。空报表、异常行、下载失败不覆盖结果。
- API 607/602/601 分别显示等待报表/权限不足/签名失败；下载链接与密钥不写日志。下载仅允许官方文档 S3 域名，不跟随重定向；其他实际域名需核对后适配。
- 当前输入总限额 5 MB、10 万行，超限拒绝，不截断后参与计算。

## 接口

均要求 superadmin：

- GET/PUT `/api/v1/games/{game_id}/taku-reports/rule`
- POST `/api/v1/games/{game_id}/taku-reports/import`：day、stage、csv_text
- POST `/api/v1/games/{game_id}/taku-reports/sync?day=YYYY-MM-DD`
- GET `/api/v1/games/{game_id}/taku-reports?day=YYYY-MM-DD&member_id=...`

无报表返回 waiting_report、空 items，不能解读为收益为零或所有用户正常。

## 部署步骤

1. 将本次后端、前端、脚本及迁移文件交付至服务器，备份数据库。
2. 使用现有生产环境变量执行 `.venv/bin/alembic upgrade head`，新增 e935_taku_reports 两张表，重启应用服务。
3. 测试页面及真实 CSV/API 数据，确认 App ID、用户映射与口径。
4. `deploy/taku-report-sync@.service` 与 `.timer` 为模板：先核对工作目录、环境文件路径及运行用户（应使用现有应用服务用户），再安装到 systemd。
5. 启用 `taku-report-sync@238.timer`。按 Asia/Shanghai 每日 04:30、13:30 查询前一日和前两日；每次执行由 systemd 同一 service 防止重叠。没有数据保留现有结果，下次计划重试。超过两天的补拉使用显式日期。

手动命令（使用同一生产环境变量）：

```text
.venv/bin/python scripts/sync_taku_reports.py --game 238 --day 2026-10-19
```
