# 会员关联筛选器：对标实测

`inspect_member_filters.py` 使用三条虚构会员，并在浏览器内拦截游戏和代理商选项查询，分别返回 ID 7200 / 6200、名称 fixture-game / fixture-agent。不修改对标业务记录。

已确认：

- 两个名称筛选器使用 SelectPage 2.20，单选、每页 10 项、可搜索、按 name 升序、显示翻页及展开按钮，输入延迟 0.5 秒。
- 选项来源为 `ajax/gameList_source/agent_ids/133` 和 `ajax/agentList_source/agent_ids/133`。133 是本次登录上下文，不应硬编码为本地固定范围。
- 选择后显示名称，隐藏值为 ID。提交列表查询实际发送 `filter={"game.name":"7200","agent.name":"6200"}`，操作符分别为 `=` 和 `LIKE`。虽然参数名包含 name，值并不是名称。
- 选择后将显示文本改成 `unselected-name`，再提交，本次观察仍提交先前 ID。仅凭文本框当前文本推导提交值会产生差异。
- 先前表格名称快捷搜索证据提交的是名称。这条路径与选择器提交 ID 是不同的客户端行为。

本地当前仍是普通文本框，`game_name` 按名称精确匹配，`agent_name` 按名称包含匹配。选择器尚未接入；不能把当前实现认定为筛选功能一致。对标服务端如何解释名称参数内的 ID、选项权限范围以及自由输入后清空规则尚未完成核验。

原始证据为 `visual-baseline/reference-verified/member-filters.json` 和 `member-filter-options.json`。后者包含插件配置、生成数据的选中值及最终查询，脚本断言所选 ID 和操作符。已取得对标公开 SelectPage JS/CSS，暂未载入页面；后续接入需同时处理认证、分页、选项权限、重置和异步响应清理，再做双端状态截图。

## 本地选项接口

已实现 `GET /api/v1/member-filter-options/{games|agents}`，复用 API 认证，返回 `items: [{id, name}]`、`total`、`limit`、`offset`。支持 `q` 名称包含搜索、`id` 精确回填、默认每页 10 项、名称升序及同名 ID 升序。`q` 中 `%` 和 `_` 作为普通字符处理。可选 `agent_id` 对游戏限定所属主体，对代理商限定该主体自身；ID 回填不能绕过该范围。返回不包含游戏密钥、主体密钥或其他管理字段。

`test_member_filter_options_paging_scope_and_literal_search` 使用临时数据库验证排序分页、范围交集、越界空页、特殊字符搜索、非法参数和认证拒绝，通过。此接口的范围是请求中显式提供的业务过滤条件，不能替代登录账号的权限模型；对标主体可见范围仍待核验。前端尚未调用此接口，选择器接入及最终筛选语义仍未完成。

## 前端接入进展

已载入相同版本的 SelectPage，并通过 `member-lookups.js` 将该控件的选项请求转换为带登录认证的本地 GET 请求。选中后提交明确的 `game_id` / `agent_id`，保留显示名称；刷新后按 ID 读取名称。原有表格名称快捷搜索仍以 `game_name` / `agent_name` 查询。重置清除选中值，路由切换或筛选区重建时清理弹层、终止请求并忽略旧响应。主体范围随选项查询传递，主体内代理商输入锁定。供应商脚本保存在 `public/vendor/selectpage.js/css`，未修改原始源码；适配层只改写本地查找 URL 和响应字段。

`verify_member_lookups.py` 验证认证头、首屏 10 条、两个控件选中 ID、提交参数、按 ID 回填、重置、名称搜索和导航后弹层清理，通过。工具栏回归通过。相同三条会员数据重新截图后，17 列宽度及行高断言仍通过，整图差异像素占比 2.9428%。尚未完成下拉面板各状态双端截图、网络失败与乱序返回测试；对标 ID 参数的服务器解释和账号可见范围仍未验证，不能据此认定筛选业务一比一。
