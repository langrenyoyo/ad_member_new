# 修复后项目复查

本轮只检查代码、临时库复现及专项测试，未修改业务代码或生产数据。

## 总体状态

注册登录、设备风控、广告可信回调、奖励快照、分段释放、标签固定奖励、代理分佣和提现具备主要实现。上一轮的孤立账务检查、关闭奖励解耦、补贴恢复与页面分离、曝光后台补报均已落地。当前仍不等同生产验收完成。

## 本轮发现

### P1：对账尚未覆盖奖励/分佣台账与实际入账的对应关系

`backend/app/wallet_audit.py:7` 检查 Member、CoinLog、Payout 和迁移归档，没有检查 RewardLedger、AppAdSession 的结算关联。

临时库为正常会员插入 10 金币 commission_1 台账，引用不存在的广告，不写金币流水、不增加钱包。实际对账输出 findings=[]、passed=True。这说明本工具仍可能漏掉“台账显示赚到了，但钱包没有入账”的数据问题；并非证明当前事务代码已经发生漏发。

建议增加广告结算与 reward 台账、实际 CoinLog 的归属/金额对应检查；分佣记录建立可追溯的 coin_log_id 或业务关联键，覆盖缺失、重复及错会员入账。完整对账通过状态不能只以余额内部恒等式定义。

### P2：公告等无关变更仍被已有可信奖励配置牵连

`backend/app/member_policy.py:237` 以提交后的完整策略决定是否校验密钥，没有比较变更字段。

临时库原策略为已启用可信 ECPM，密钥文件不可读，仅修改 announcement 并保持奖励配置不变，PUT 返回 503；提交 reward_enabled=False 返回 200。因此“关闭奖励”已经修复，但“无关公告修改可用”尚未完全满足。

建议在同一事务读取原策略，区分启用/修改结算依赖与无关字段变更；广告准入仍严格拒绝无效密钥，避免以管理入口可用性为由降低结算验证。

### P2：后台任务取消后的冷却状态存在覆盖

`BackgroundRetry.kt:24` 的 cancel 将 nextStart 清零，但被取消任务的 finally 在 `:19` 又写入当前时间加 30 秒。退出后快速登录的新会话可能无法立即触发补报，且当前只是触发式调度，没有定时唤醒来补这次被忽略的触发。

这是静态代码路径发现，未进行真机时序复现。建议使用任务代次或身份判断，只有当前任务能更新冷却；取消后旧任务不能覆盖新会话调度状态。现有测试调用 cancel 但未验证取消完成后的立即重启。

## 持续存在的边界

- SDK 广告名称/行业字段不保证返回；当前类别主要依赖人工复核，没有 OCR/AI 自动识别及平台核减确证能力。
- 补贴未提交草稿、普通补贴恢复和元数据持久化补报尚未完整实现；Android 的网络、存储及进程死亡端到端测试仍不足。
- 设备观测仍全量读取活跃 peers，对账按会员加载流水；大数据量性能需压测。
- PostgreSQL 存量迁移、真实风控/广告/支付联调未验收；SQLite 通过不能替代它们。
- APP、新模块和迁移仍有未跟踪文件，交付时须完整纳入版本管理，继续排除凭据。

## 验证口径

本轮重跑资金专项与会员策略专项，并独立复现上述两项后端问题。上一轮全量 185 项、Android 28 项测试及构建/Lint 通过，本轮不冒充重新完成全量、真机或生产验收。

建议先完善业务台账对账与相关测试，再处理策略变更判定和后台调度取消边界，最后进入生产副本及真机验收。
