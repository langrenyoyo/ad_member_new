# 设备风控对照核验（2026-09-18）

本轮修复了设备页把风险事件当作会员展示的数据契约错误，并补齐参考列表和操作界面。真实设备风控名单尚未接通，不能将本页或整站标为完成。

## 数据来源缺口

参考 `risk/userd` 控制器明确使用会员 ID、账号、金币、白名单/状态开关及会员编辑、金币调整、单/多 APP 入口。原本地 `/risk/devices` 返回 `RiskRecord`，其中 `id` 是风险事件 ID，不能传给 `/members/{id}`；只更换前端列和操作会造成对象错配。

重新运行 `inspect_reference_device_scope.py`，参考设备名单仍为 0 条；同账号会员列表有 7 条，`device_id_ban` 均为 0。只保存总数、字段名称和标记分布，未保存会员账号、设备标识或密码。该空正样本不能证明名单按设备封禁、风险标志或重复关联入选。

因此 `/risk/devices` 已移除错误的风险日志查询，当前明确返回 HTTP 503，显示“设备风控名单暂不可用，请稍后重试”，不伪装成成功的空名单。风险事件仍由 `/risk/history` 正常查询。没有将 `device_id_ban`、`risk_flag` 或风险日志关联擅自当作入选规则，也没有创建替代名单表或导入假数据。

已请求设备名单入选规则或可读取的后端源码路径。确认后需恢复真实会员查询，再验证筛选、分页、操作后的入选/退出行为与权限范围。本轮模拟名单测试不构成该部分的证据。

## 已确认界面

`inspect_device_risk_parity.py` 在登录后拦截业务写请求和已知变更 GET，向参考页面注入三条模拟会员；保存控制器、权限、列配置、控件几何、截图与下载文件于 `visual-baseline/fixtures/device-risk/`。

- 24 个数据/操作列，默认加勾选列共 14 列；默认 Id 倒序，六种页大小 10/15/20/25/50/All。筛选默认收起。
- 账号、上级 ID、代理商、昵称、状态、创建时间为可用筛选，第三个位置保留参考空游戏筛选区域。
- 参考游戏列未定义标题，表头及导出字段名为空，卡片没有标题占位。点击游戏名不发查询，但会切换该行勾选；已捕获并恢复此行为。
- 参考账号可见单 APP、多 APP、修改金币和编辑。删除、工具栏批量启停与清空金币隐藏。使用会员开关，名单本身没有单独的“新增”操作。
- 有勾选时导出选中行，否则导出全部查询结果；不跨页保留勾选。排除选择和操作列，尊重隐藏列。

设备页复用 `whitelistColumns`、`whitelistCell` 和 `mountWhitelistActions`，增加可选的游戏选择器及全选文字参数；默认白名单行为保持原状。代理选择器复用 `attachFilterLookups`，允许表单仅有其中一种选择器。样式复用白名单已验证布局，设备页补充无标题卡片的排版。

## 模拟数据验证

`verify_device_risk_parity_browser.py` 拦截所有业务读写，以 225 条内存会员验证：接口失败不显示假空表格及会员操作；重试；勾选/选中导出；游戏名勾选；代理商 ID/名称与普通筛选；日期弹层/无效日期；状态开关失败重试；会员编辑、金币调整、单/多 APP 范围；列选择、排序、All 分批；旧请求和离页隔离；路由返回状态以及 1920/1024/390px 边界。手机截图在 `visual-baseline/verified/device-risk-mobile.png`。

开关用模拟 PATCH 修改实际会员字段。模拟名单在白名单开关变化后仍返回该会员，只用于验证操作 ID 和刷新，不代表真实设备名单规则。

| 状态 | 两端尺寸 | 差异像素占比 |
|---|---|---|
| 默认表格 | 1660×320 | 0.0113% |
| 展开筛选 | 1660×416 | 0.0618% |

参考视口 1690px 等于本地 1920px 减去侧栏；任一 RGB 通道差值超过 16 计为差异。指标只对应相同模拟记录和页面状态，不能代表完成度。全量及选中两组 JSON/XML/CSV/TXT/Word/Excel，12 个内容比较全部一致；JSON 按结构、XML 按标准解析器正规化后比较。

70 项临时数据库后端测试、35 个 JS 语法检查通过；新后端测试确保风险事件不会作为设备会员返回，原风险历史查询仍可读。设备模拟交互、白名单完整交互、三页搜索选择器及白名单同数据截图/导出回归通过。修正两份浏览器测试的等待条件，使其等待开关刷新完成再断言，避免请求尚未结束时读取旧状态。
