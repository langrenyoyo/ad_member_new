# 2026-10-11 需求简化版

依据：`20261011需求.txt`。本文件用于业务确认，示例数值不作为上线默认值。

## 一、目标

减少快手最终收益核减，降低人工排查成本；识别用户观看的广告，按广告标签和 ECPM 灵活配置奖励。不能保证自动识别快手未公开的核减原因。

## 二、功能需求

| 功能 | 需求说明 |
|---|---|
| ECPM 分段释放 | 后台自定义 ECPM 区间及释放比例，实现低 ECPM 高释放、高 ECPM 低释放。ECPM 单位为“元/千次”，各平台原始数据须正确换算。此功能与核减判断独立。 |
| 广告内容识别 | 尽可能识别实际展示的广告名称和类别，如游戏、交友、金融理财、电商购物。优先使用平台字段；字段不足时验证 OCR/AI 的可行性。无法识别显示“未知”。 |
| 用户广告标签 | 统计用户观看各类广告的次数和占比，达到后台配置的样本量及比例后生成标签。例如金融类占比超过 50%，仅为待确认示例。 |
| 标签奖励 | 后台可为不同标签设置固定奖励，如金融、电商类发 10 或 20 金币，金额可自定义。 |
| 异常用户排查 | 汇总广告记录、标签和已有风控信号，辅助运营排查疑似导致核减的用户；支持人工复核。 |
| 异常用户限制 | 判断依据确定后，可在请求或展示前拒绝向异常用户提供广告。依据未明确前先做观察，不自动拦截。 |
| 后台查询 | 查看会员广告名称、类别、ECPM、标签占比、奖励金额、规则及风险原因，便于追溯。 |

## 三、实施顺序

1. 先完成 ECPM 分段释放配置和计算。
2. 验证广告平台字段及素材获取能力，接入广告识别和展示。
3. 完成用户标签统计、人工纠正和固定金币配置。
4. 确认异常判断标准后，再启用自动限制。

现有自定义固定 ECPM、平台释放比例可继续使用，但不能代替新增的 ECPM 分段规则。

### 自定义 ECPM 设置方式（补充截图）

按截图采用两行输入，英文逗号分隔，位置一一对应：

```text
自定义 ECPM：50,100,200,300,500,1000,2000,3000,4000
自定义比例：200,70,70,70,65,60,50,40,30
```

- ECPM 单位为元/千次，表示分段阈值，不是强制改写平台真实 ECPM。
- 比例单位为百分比：200 表示 200%（2 倍），70 表示 70%（0.7 倍）。分段比例必须支持超过 100%，不能沿用平台比例 0–100% 的限制。
- 两行数量必须一致；阈值非负、严格递增；比例非负；拒绝空项、重复阈值和非法数值。比例最大值另行配置或确认，不设为无上限。
- 保存前展示区间表及奖励试算；业务规则按广告会话保存快照。
- 当前按建议实现：阈值为包含边界的上限，超过末档沿用末档比例，分段比例替代平台比例；支持 0–1000%。配置按本次广告可信人民币 ECPM 计算。
- 原有“固定 ECPM”与本次“ECPM 阈值分段”须分开命名，避免混淆。

## 四、必须确认的规则

1. 分段依据：本次广告 ECPM，还是用户近期平均 ECPM？具体区间和比例是多少？
2. 标签依据：统计最近多少次或多少天？至少多少条广告？达到多少占比生效？
3. 固定金币：按本次广告类别发放，还是按用户标签影响之后的广告？
4. 规则叠加：固定金币、分段比例、平台比例、白名单倍率和奖励上限，谁优先？
5. 异常标准：哪些信号触发限制、限制多久、如何人工解除？

## 五、验收与边界

- 区间无重叠、边界计算正确；奖励规则可追溯，重复回调不重复发奖。
- 识别不到或样本不足时明确提示，不生成虚假类别或异常结论。
- 观察阶段不影响奖励；已有效完成的广告不因事后识别而自动取消奖励。
- 广告标签不等于作弊证据；平台核减原因与本地推测分开显示。
- 广告采集受 SDK 能力、系统授权和平台规则约束，需实测确认。
- 原文图片及语音仅有占位，未包含其具体内容，需补充后再确认是否新增需求。
