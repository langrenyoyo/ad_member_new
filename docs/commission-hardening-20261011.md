# 代理与分佣修复（2026-10-11）

## 本次实现

- `commission_enabled` 独立控制分佣。开启分佣且关闭自定义奖励时，以原结算奖励为基数；关闭分佣不影响自定义奖励。旧配置未设置该字段时沿用 `reward_enabled`，防止升级直接改变支付行为。管理端加载旧规则后显示实际开关状态。
- 广告申请时保存版本 2 快照：规则、白名单状态、各级受益会员 ID。回调不重新选上级；升级不改变旧广告对应比例，降级低于快照等级、封禁、删除、跨游戏和自分佣均跳过，不递补其他人。指定全局代理须为本游戏正常状态的代理会员。
- 历史广告的旧快照仍兼容，按旧归属方式结算并标记 `legacy_callback`；无法反向补造历史邀请链。
- 佣金写入金币余额与流水，和广告奖励同事务；唯一键及原回调幂等共同防止重复支付。
- 后台奖励/分佣流水显示总数和每页 50 条翻页，修复乱码。APP 分佣收益页显示北京时间今日收入、累计收入、等级、直属邀请人数；直属邀请页可分页查看会员编号和等级，不暴露手机号和收款信息。

## 业务边界

- 仍为每游戏一名指定全局代理；不代表多代理共享全应用收入。邀请链按每个等级最近的有效上级选取。
- 分佣是用户最终奖励基础上的额外支出，记入现有金币钱包；不是广告收入会计对账，也没有新建独立佣金提现账户。
- 新策略由可信 TAKU 服务端回调结算。旧非 TAKU 客户端完成路径没有扩展为可信分佣来源。
- 本次未引入收入核减、佣金冻结或冲正。现有广告回调未提供核减凭据；此类财务流程需明确核减来源、可追回余额和已提现欠款的处理规则。
- 不修改生产配置，不自动启用分佣。不需要增加数据库列，配置与快照存入已有 JSON 字段；首次部署仍需完成既有 e929 迁移。
