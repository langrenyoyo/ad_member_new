# 会员头像文件持久化

已替换原先把 data URL 写入 255 字符头像列的做法。编辑器使用 `POST /api/v1/member-images` 上传二进制文件；后端要求操作员权限，限制请求体 2MB，使用 Pillow 解码 PNG/JPEG/WebP/GIF，并将第一帧规范为无原始元数据的 PNG。宽高上限为 4096 像素。这些是本地当前支持范围，尚未与对标上传限制逐项核实。

文件使用随机名称保存到 `backend/uploads/members`，可通过 `MEMBER_IMAGE_DIR` 指定持久目录。接口返回短地址，会员保存时只写入该地址。`/api/member-images/{随机文件名}` 公开读取规范化后的头像，不提供文件列表；数据库备份必须同时覆盖图片目录。多实例部署需要共享持久存储。

上传成功不等于会员保存成功。用户取消编辑或更换图片可能留下未引用文件；当前尚无孤立文件清理任务。GIF 动画仅保留第一帧。真实对标的附件选择、裁剪或动画行为尚未验收。

前端上传期间禁止提交；重新选图、重置、关闭或导航使旧请求失效。重置同时恢复头像地址和预览；错误保留原值并允许重试。

手动编辑头像地址现在同步预览；清空地址隐藏预览。手动修改会取消正在进行的上传并使其迟到响应失效，防止旧上传覆盖用户输入。按钮标为“上传”，与其实际本地文件上传行为一致。

只读核查对标 `/general/attachment/select` 返回“你没有权限访问”，未出现列表或表单。证据见 `visual-baseline/reference-verified/member-attachment.json`，采集脚本为 `inspect_member_attachment.py`。这仅说明当前账号的访问结果，不能证明完整附件选择功能不存在。附件选择仍未实现和验收，需要具有附件访问权限的对标证据；未用自拟列表冒充对标实现。

验证：后端隔离测试覆盖真实 PNG 上传、取回像素解码、会员地址持久化、损坏文件、超限大小、权限及地址长度；浏览器模拟覆盖迟到请求、连续选图、重置、关闭重开、失败重试及仅提交短地址。测试只使用临时目录和隔离数据，不写业务记录。
