# 四项复查问题修复

## 变更

- 对账改为额外扫描全表关联：不存在会员的金币流水和提现、缺失提现主记录、提现会员或游戏不匹配、未知提现状态均产生差异。即使会员表为空也不会漏过孤立记录。孤立流水的金额等式同样检查。工具仍只读，不自动补账。
- 后台保存策略仅在启用依赖可信证明的奖励时执行密钥强校验。关闭奖励、保存不依赖证明的配置可以在 keyring 故障时执行；广告准入仍单独执行失败关闭校验。
- 活动补贴恢复独立于会员页面加载，显示单独状态和手动重试按钮，不占页面 busy 状态。恢复与提交路径中的恢复使用互斥锁，沿用原请求键；网络/5xx 保留原记录。
- 曝光补报改为应用内后台任务。初始化、钱包和曝光入口只触发任务，不等待整个上传队列。全应用共享单个工作任务；每批最多 20 条、45 秒协程预算，结束后至少间隔 30 秒再接受触发；暂时性网络/服务端错误结束本批并保留记录。已有网络连接/读取超时仍适用，阻塞网络操作的取消可能等待底层超时，45 秒不是硬断线承诺。
- 退出账号取消工作任务、清理记录，原会话 epoch 仍防止旧请求修改新会话状态。未添加系统后台定时唤醒，后续重试由应用运行中的入口触发。

## 验证

新增后端回归覆盖空会员表孤立数据、错误流水、缺失提现关联和未知状态，以及密钥故障时关闭/启用策略的不同结果。新增 Android 测试覆盖工作任务合并、前台不等待后台、失败后的冷却。

后端全量 185 项测试通过（111.055 秒）；Android debug 构建、28 项 JVM 测试及 Lint 通过，git diff --check 通过。尚无真机弱网、杀进程或 PostgreSQL 生产副本验证；自动广告识别、完整资金外部对账不因此视为完成。未部署或操作现有业务数据库。
