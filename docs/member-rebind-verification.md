# 会员改绑关系核验

已在主会员列表补齐“改绑关系”入口，行操作按对标排列为改绑关系、单 APP 行为、修改金币、图标编辑。状态和白名单仍由对应列开关操作。

只读检查对标表单确认：当前 ID 输入框禁用，上级 ID、归属 ID、源头 ID 可编辑，底部为确定和重置。本地使用现有 `parent_id`、`ht_id`、`ht_top_id` 字段，保存经现有会员 PATCH 接口提交三个整数，不提交当前 ID。重置恢复读取值；失败保留输入并允许重试；保存进行中不重复提交；关闭或切换页面后的响应不刷新其他页面。共用窗口逻辑保留拖动、最小化、最大化。

验证范围：

- `verify_member_rebind.py` 用浏览器模拟响应验证表单生命周期、零值提交、非整数拒绝和权限失败。
- `test_member_relation_fields_atomic_roundtrip` 用临时数据库验证三字段持久化、风控角色拒绝、空值/非整数失败时整次更新不落库。
- 原金币弹窗和会员工具栏回归通过。
- `inspect_member_rebind.py` 在两端注入相同虚构 ID，采集 800×600 弹窗。当前差异像素占比 0.4975%，截图保存在 `visual-baseline/fixtures/member-rebind`。对标业务写请求在登录后全部拦截，未提交保存。

尚不能证明业务完全一致：对标服务器是否校验目标会员存在、是否禁止关系环、是否连带更新下级关系、空字符串如何处理均未验证。本地本次沿用已有三个字段的直接持久化行为，没有凭空加入自动关系推导。截图比率受大面积空白影响，不是业务或视觉完成率。当前 ID、字段位置和默认窗口已采集，其他窗口状态未重新进行双端截图比较。
