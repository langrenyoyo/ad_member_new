# 主会员列表批量启用与禁用

对标工具栏源码包含“更多”“启用”“禁用”，但后续可见性实测确认：其父容器为 `dropdown btn-group hide`，选中会员后仍为 `display:none`。证据见 `visual-baseline/reference-verified/member-batch-confirmation.json`。此前把源码存在误判成可用入口，现已纠正：本地主列表默认隐藏整个批量菜单，批量接口及处理函数保留。尚不能确定对标隐藏原因，不能凭猜测映射为具体角色权限。

`POST /api/v1/members/batch-status` 接收 ID 列表及 0/1 状态，要求操作员权限，最多 200 个 ID，去重处理。若提供主体范围，所有记录必须属于该主体；记录不存在、状态无效或范围不符时整批不修改。前端主体页面携带当前主体范围；这是业务范围一致性校验，不替代账号级数据授权。

`verify_member_toolbar.py` 验证主列表默认及全选后批量菜单都不可见。`verify_member_batch_status.py` 首先验证默认隐藏，再使用明确的测试专用显示注入，覆盖处理函数的无选择禁用、选中 ID、提交期间禁用、失败保留选择、成功清空及跨主体迟到响应隔离。测试专用显示不表示生产页面或对标账号具有该入口。后端 `test_member_batch_status_scope_atomicity` 覆盖权限、范围、缺失记录、无效状态、重复 ID 与整批原子性，均使用隔离数据。

尚未验收对标批量确认弹层、提示文案、菜单像素及对标服务端行为；本次只补齐已有明确入口对应的本地批量操作。不支持将超过 200 条的大批次拆成可能部分成功的多个请求。
