# 鸭只易记 APP API 接口文档

版本：2026-11-08 · 当前本地后台代码版 · 面向用户 APP 开发与联调

## 1. 范围与文件

本文按实际 FastAPI 路由、参数模型和业务实现重新生成，入口为 `backend/app/main.py`，不包含管理后台 `/api/v1` 和服务端广告平台回调。附带 OpenAPI JSON、Postman Collection 和 Word 版。完整参数附录由运行时模型生成，非旧文档拼接。

新增副广与内容采集修改尚在本地；本文不代表生产服务器已部署同一版本。联调前应核对部署版本，新增接口返回404时先核对服务器版本。

- APP 前缀：`/api/app/v1`，例如 `https://<实际API域名>/api/app/v1/auth/login`。
- 本地默认服务：`http://127.0.0.1:8000`；真机的127.0.0.1指向手机自身，需使用可访问的开发机地址。
- 实际域名由部署方提供。文档、OpenAPI、Postman均不包含生产密钥或真实用户令牌。
- Swagger：`/docs`；完整在线契约：`/openapi.json`。附带 JSON 仅保留 APP 接口及其引用模型。
- 日期、ID、截图URL和 SDK 字段示例均为占位数据；提交时使用真实返回值和当前时间。

## 2. 通用调用约定

### 2.1 请求头与认证

```http
Content-Type: application/json
Authorization: Bearer <access_token>
X-Device-Id: <安装实例标识>
X-App-Id: ad-member
X-App-Version: 1.0.0
X-Platform: android
```

公开接口不加 Authorization；其余接口使用用户 Access Token。Refresh Token 只放刷新/退出请求体，不能当Bearer Token。`X-Device-Id`应在当前安装生命周期内稳定，和登录/广告请求体`device_id`一致。上述X头不是所有接口都由参数模型强制校验，但设备策略和观测关联会使用它们；带设备字段的请求体仍必须填写。`X-Device-Risk`如使用应传实际检测结果，不能代替服务端风控校验。

公开接口：注册、密码登录、两个微信登录路径、刷新、发送短信、短信登录、读取`policy`。短信设置密码、微信设置密码均需先登录。

### 2.2 响应与错误

成功一般为 `{"data": {...}, "request_id": "..."}`，部分扩展接口只有data。204无响应体，不能强行JSON解析。列表items为空是正常业务结果。

错误兼容三种形式：

```json
{"detail": "业务提示字符串"}
```
```json
{"detail": {"code": "INVITE_REQUIRED", "message": "请先绑定邀请码"}}
```
```json
{"detail": [{"loc": ["body", "password"], "msg": "校验提示", "type": "校验类型"}]}
```

优先读`detail.message`，其次字符串detail，校验数组按字段展示；不要把所有422显示成密码错误，或所有409显示成账号已注册。部分历史服务端文案存在占位字符，APP可按明确code映射可读文案，未知错误保留诊断信息。

| HTTP | APP处理 |
| --- | --- |
| 400 / 422 | 校验参数或证明，不盲目重试 |
| 401 | 受保护接口可尝试一次串行刷新；登录/验证码失败直接处理对应错误 |
| 403 | 按code引导邀请码、支付宝、使用统计授权或设备限制，不循环刷新 |
| 404 | 资源/配置不可用，或服务器未部署该接口 |
| 409 | 业务冲突、重复键内容不一致、过期/状态不允许，显示真实原因 |
| 410 | 原申请已删除，联系管理员核对，不能假定幂等成功 |
| 413 | 图片过大，压缩后重新上传 |
| 429 | 按响应提示等待；并非所有路径提供Retry-After头 |
| 502 / 503 | 第三方或配置不可用，不伪造登录、奖励或提现成功 |

若响应存在`X-App-Audit-Id`，可连同request_id记录用于排障；日志不要输出Token、密码、验证码或完整收款账号。

### 2.3 分页与数据类型

分页接口支持`page=1&page_size=20`，兼容`limit=20&offset=0`。`page`从1开始、`offset`从0开始，条数1–100。优先级：size=`page_size`否则`limit`；有page时offset=`(page-1)*size`，否则使用offset。建议统一使用一套参数。

```json
{"data":{"items":[],"total":45,"limit":20,"offset":20,"page":2,"page_size":20,"total_pages":3,"has_more":true}}
```

以上items为空仅示意结构。下一页只有在请求成功后才推进，重复失败保持当前页；切换筛选重置第一页。适用：广告历史、活动、申请、提现、金币流水、佣金、直属团队；games不分页。

时间采用ISO 8601；客户端发送事件时间应带Z或时区。业务“今日”按北京时间计算。提现和活动的`*_cents`单位为分，补贴申请`price/tx_price`单位为元，金币为十进制数值/字符串，客户端应使用十进制处理而不是浮点累加。不要把金币数直接当作人民币。

## 3. 推荐接入顺序

1. 读取`GET /policy?game_id=...`，展示公告和注册条件。
2. 密码注册/登录、短信或微信登录，保存user及两枚Token。
3. 查询`GET /onboarding`，按策略补齐邀请码、支付宝、使用统计授权。
4. 调用`GET /bootstrap`获得游戏和SDK广告配置，读取`GET /invite-code`展示本人邀请码。
5. 钱包、补贴、广告、佣金等页面分别调用对应接口。冷启动恢复先刷新/验证会话，SDK初始化后按配置加载。
6. Access Token过期时合并并发刷新，原子替换两枚Token；失败回登录。退出清除当前账号状态，晚到的SDK回调不能归入新账号。

身份以onboarding/invite-code的level为准：0普通会员、1团长、3代理；不要用`vip`字段推断邀请资格。所有会员可展示自己的6位英文数字组合邀请码，但只有本应用正常团长/代理可用于强制邀请码注册及绑定上级。

## 4. 广告接入与内容采集

### 4.1 激励链路

风控开启时：config → challenge → 阿里云SDK → verify → ads/request。关闭时可直接申请激励。

将`ads/request`返回的`ad_unit_id`、`taku_user_id`、`taku_extra_data`交给对应SDK配置，按SDK展示回调发送impression和metadata(shown)。拿到激励达成回调和完整人民币eCPM加密证明后调用complete；失败走fail。SDK关闭回调只记录closed，不代表奖励达成。

固定价格证明需要先完成shown元数据上报，再发送complete；客户端应在本地持久化事件，保留原事件ID、SDK请求/展示ID和会话Token重试。不能用观看秒数、明文publisher_revenue_cny或客户端估算金币代替证明。以complete返回和wallet查询确认到账，重复完成不重复发放。

SDK证明字段：`e_c`为美元加密eCPM（可选），`e_c_cny`为人民币加密eCPM，`s_id`为SDK secretId字符串，`source_id`为广告源ID，`sdk_request_id`和`sdk_show_id`分别对应SDK请求与展示ID。所有字段原样取自本次SDK广告信息，不自行生成。激励事件的`occurred_at`可选，impression/fail等状态时间当前主要按服务端接收时间记录；副广occurred_at则实际用于观看时间。

### 4.2 副广链路与类型

副广直接使用bootstrap配置的广告位加载，实际SDK回调上传`POST /ads/secondary-events`，不调用激励申请/完成接口。

| 类型值 | 名称 | is_fu | fu_type |
| --- | --- | --- | --- |
| rewarded | 激励视频 | 0 | APP历史为null |
| splash | 副广·开屏 | 1 | 1 |
| banner | 副广·横幅 | 1 | 2 |
| interstitial | 副广·插屏 | 1 | 3 |
| native | 副广·信息流 | 1 | 4 |

每次实际展示使用新的UUID；同一次展示的shown、clicked、closed共用UUID。横幅刷新到新的展示应使用新UUID。副广不增加金币，也不影响激励奖励标签样本。

### 4.3 历史内容字段

`GET /ads/history`条目含：id、game_id、placement、ad_type、provider、status、coin_added、request_id、watched_at、created_at，另有下表字段。用户广告内容来自SDK；人工复核标题优先。SDK未返回名称时不能承诺识别具体商品，历史未采集内容无法补回。

| 字段 | 含义 |
| --- | --- |
| is_fu / fu_type / ad_type_label | 主副广标识、细分类别、展示名称 |
| ad_title / ad_app_name / ad_app_package | 广告名称、应用名、包名 |
| ad_creative_id / ad_advertiser | 素材ID、广告主 |
| ad_network / ad_source_id / ad_network_placement_id | 实际平台、广告源、平台广告位 |
| ad_content_status | reported=已采集名称；sdk_not_provided=SDK未提供名称；not_collected=未采集 |
| ad_content_source | manual_review / client_reported / unknown |
| ad_behaviors | shown、clicked等已采集行为数组，不应当作平台结算证明 |

内容品类（游戏/交友等）与广告形式是不同维度，客户端不要依据广告名称自动产生结算标签。

## 5. 补贴活动与审核到账

活动公告使用`GET /subsidy-campaigns`，登录规则公告使用`GET /policy`的announcement。活动列表每次正确递增page/offset，可浏览超过20条；无活动时展示空状态。

活动字段：id、game_id、title、enabled、daily_quota、withdrawal_cents、recharge_cents、reward_cents、review_hours、instructions、created_at、updated_at；资格附加quota_date、used、remaining、confirmed_withdrawal_cents、eligible、reasons、required_images。

进入详情重新查询资格；申请前分别上传下载、安装来源、充值三张不同图片，拿上传返回的相对URL提交。展示图片时以API域名拼接URL，使用`GET /api/member-images/{filename}`，该图片读取路径在APP前缀之外，不要再加/api/app/v1。服务端按活动快照和当日确认提现核验，不能提交自定义补贴金额。审核时长是配置目标，超时不自动审核；campaign.review_due_at和overdue可用于状态提示。

申请状态：`status=0`待审核、`1`通过、`2`驳回；`target_status`把驳回映射为4。申请列表筛选仍用status=2。审核通过会在同一事务中按“补贴元金额 × 审核时后台金币/元比例”增加金币并写入type=302流水，不执行支付宝现金转账。客户端刷新wallet和coin-logs确认；申请详情不提供独立coin_added字段，不能拿当前前端比例推算并直接改钱包。

## 6. 提现与账号限制

先查询收款绑定和withdrawal-options，根据服务端tiers显示档位；payment_available=false时显示服务暂不可用。POST withdrawals成功表示申请和冻结金币成功，不代表到账。以payout.state=succeeded确认渠道成功；驳回/失败根据后台业务处理释放冻结金币，客户端刷新钱包核对。

403可能携带INVITE_REQUIRED、ALIPAY_REQUIRED、USAGE_REQUIRED、DEVICE_COOLDOWN或RECOVERY_ONLY。受限恢复Token仅允许有限的读取/提现/退出等路径，不应使用循环重试绕过。require_usage开启时需周期同步授权状态，过期后重新引导。

### 8.5 POST /api/app/v1/auth/refresh

Refresh Token 轮换：旧 refresh_token 在成功后撤销；原子保存响应中的 access_token 和 refresh_token。同一账号设备的刷新请求应串行合并。服务端默认 Access Token 120 分钟、Refresh Token 30 天，以部署配置及 expires_in 为准。

鉴权：公开接口。

## 10. 联调检查与交付说明

- 导入OpenAPI到Apifox/Swagger，或导入Postman Collection后设置base_url。base_url不包含/api/app/v1，路径已带前缀。Postman成功登录/刷新后自动保存两枚Token，成功申请激励后保存会话ID/Token。上传请求请在Body中选择真实图片文件。
- 示例game_id=238不表示任意环境均存在该游戏；必须使用部署方指定ID。邀请码、验证码、图片URL、当前时间、SDK证明均需替换，示例不是可直接成功的生产请求。
- Token轮换应由同一会话单处管理；检查退出、切账号后的晚到广告回调不会串入其他账号。
- 验证激励及四类副广分别显示，副广重复提交不重复记记录、不发金币；缺名称时显示真实采集状态。
- 验证补贴第2页及后续页、三图上传、资格不足提示、审核后刷新钱包及type=302流水。
- 验证提现未配置渠道时明确不可用；申请成功、审核通过、渠道到账三个状态要区分。
- 不存在APP端审核补贴/提现接口，不应把管理员Token打包进APP；不存在通用未登录重置密码、任务/签到/商城/题库的APP服务端接口。本地功能不能臆接不存在的路径。
- 本套文档覆盖实际注册的43条路径、49个HTTP操作。生成过程中只导出本地路由与模型，未启动lifespan、未连接业务数据库、未访问生产接口。
- 历史文档docs/app-frontend-api.md面向管理端，不适用于用户APP；本文件为2026-11-08用户APP接入版本。
