# APP 端二次复查（新增需求实现后，2026-10-10）

结论：功能入口已增加，但仍有业务阻断和生命周期缺口，不能判定 APP 已完善或正式上线可用。此次只审查代码与现有测试报告，未修改业务代码、未重新构建，也未调用线上服务。ADB 无连接设备。

## P1：优先修复

1. **短信新用户未设密码会卡在强制支付宝页。** LoginScreen 明确允许密码留空（IdiomQuizApp.kt:1278），后台为新用户生成随机密码；OnboardingScreen.kt:42 要求当前密码，而第 43 行起只给微信用户提供设密入口。手机号用户无法在引导内完成设密，只能退出、重新获取短信并在登录时设密。应提供独立短信验证设密步骤或在新用户流程明确要求设置密码。
2. **一次规则刷新失败导致全屏阻断并停止自动恢复。** QuizViewModel.kt:124 刷新失败设置 onboardingError；IdiomQuizApp.kt:163 将任何错误视为需进入引导并提前 return。第 168 行的定时刷新 LaunchedEffect 随之离开组合，网络恢复后也不会自动重试，用户只能手动刷新。进入该分支还会销毁会员中心的手工 ViewModelStore，丢失编辑/申请状态。应区分首次加载未知、业务门禁、已有配置下的暂时网络故障，并独立维护重试任务。
3. **冷却期挡住 APP 提现确认。** 后台允许钱包及原提现查询恢复，但 onboarding 会因 DEVICE_COOLDOWN 返回 403；APP 因上述全屏门禁只显示刷新和退出。IdiomQuizApp.kt:1588 的“确认上次提现”按钮存在，却无法进入钱包使用。应在冷却页展示服务端 blocked_until，保留提现记录与原申请确认等恢复入口。
4. **使用权限撤销后的更新不与前台生命周期绑定。** 仅使用 Compose 的 60 秒循环，无 ON_RESUME 检查；从设置返回必须手动确认，切后台仍可能继续统计和请求。撤权到下一次检查之间可继续使用本地功能，服务端对历史授权报告另有 15 分钟有效期。应在前台恢复即时检查，后台停止采集，并将权限变化与门禁状态联动。

## P2：可靠性和交互

5. **普通微信登录没有超时恢复。** QuizViewModel.kt:518 将 authBusy 置 true，只有 SDK 事件或立即启动失败会复位。120 秒超时目前仅覆盖微信设密；无回调时所有登录按钮可能一直禁用。应统一授权生命周期并提供取消重试。
6. **短信界面与错误提示混用密码语义。** 同页面重复手机号输入，验证码按钮复用下方密码字段作为“设置/重设密码”；没有明确的登录方式切换与设密确认。AuthRepository.kt:267 将所有 401 显示为手机号或密码错误、所有 422 显示密码复杂度错误，验证码失效/格式错误会误导用户。发送冷却直接 return，按钮仍可点击且无实时倒计时。
7. **会话隔离尚未覆盖整个业务操作。** showRewardedAd 在 SDK getDeviceToken 等待之后才捕获 epoch（QuizViewModel.kt:395）；此前退出/切账号，后续请求可能用新凭据携带旧 challenge，通常被后端拒绝，但会影响新界面状态。initializeApp 的多次请求也没有共同的操作代次。需从操作开始绑定会话，并在 SDK 等待、重试与每次 UI 更新前验证。
8. **引导和会员表单状态容易丢失。** OnboardingScreen 使用 remember；旋转、页面重建会清空支付宝姓名、账号、邀请码等输入；密码不应明文持久化，但普通表单应按用户保留。会员中心离开页面即清理自建 ViewModelStore，补贴图片和幂等键仍不能耐重建。
9. **应用打开次数仍是估算。** 使用前台/后台事件计数，应用内 Activity 切换也可能计数；queryAndAggregateUsageStats 是系统区间聚合，不能保证返回严格当日边界。统计应标注估算，必要时用事件重建区间并测试跨午夜、多窗口等场景。
10. **测试对新增客户端业务覆盖不足。** 23 项 JVM 测试主要覆盖解析、规则和 SessionFence；没有新增引导状态机、短信登录、权限撤销、网络恢复、冷却页提现恢复、真实微信回调或 Compose 导航测试。编译和 Lint 通过不证明这些路径可用。

## 已确认存在的入口

短信/密码/微信登录，邀请码绑定，微信设密，支付宝绑定，使用权限设置与上报，公告展示、邀请码展示、分佣分页流水，提现持久化幂等键与独立确认按钮，阿里云 challenge/token/verify 和广告服务端到账轮询均有代码。没有把新增入口缺陷等同于这些功能完全缺失。

## 验证与下一步

现有报告：23 项 JVM 测试，0 失败；Lint 0 错误、92 警告、2 提示。当前没有真机，未验证真实 SDK、权限返回或支付。新版 APP 必须配套部署 onboarding 等后端接口，否则登录后会停在设置加载错误页。

建议先修复 P1 的引导/门禁状态机和恢复入口，再补普通微信超时与短信交互，随后做弱网、旋转、切账号、撤权和冷却期提现的定向测试。完成真机联调后再判断是否具备发布条件。
