# 主体列表与 OSS 核验（2026-09-18）

本轮覆盖主体列表与 OSS 配置窗口，不代表主体统计、分析、游戏配置或全站已完成一比一。

## 参考证据

`inspect_agents_parity.py` 登录后拦截非 GET/HEAD 和危险路径。列表注入三条合成记录；OSS 仅 GET，响应中的四项配置通过 HTMLParser 替换为合成值后送入浏览器。未写参考业务数据，未保存真实 OSS 表单或密钥。

控制器证实 Id、创建/更新时间可排序；无全局搜索；名称、状态、双日期筛选；隐藏穿山甲 user_id、role_id、security_key、更新时间。父主体有“进入”，下级无此按钮。

当前参考账号的编辑、删除权限为空，“更多”的父容器为 `hide`。本地不为截图禁用已有操作，而由 `/agents` 的 `permissions` 返回本地角色能力：superadmin/operator 可新增、编辑、删除、OSS、批量状态，其他登录角色只读及进入统计。对比脚本注入与参考相同的能力组合，故该结果不证明两站完整权限模型相同。

## 实现

- 列表接入共享表格：页大小 10/15/20/25/50/All、首尾循环、跳页、排序回首页、列/卡片、选择/全选、刷新与状态保留。All 与全量导出以 200 条分批，检测总数变化、重复 ID 和不完整结果。
- 名称/状态及双日期交集；拒绝无效日期、倒序范围和 Date 自动滚动的日期。离开页面销毁控制器，取消读取和导出，过期返回不重绘。
- 新增批量状态接口：1 至 10000 个 ID，去重，状态只接受 0/1，同一事务全量校验，缺失记录 404 且不部分更新。operator/superadmin 授权；前端锁定重复提交，失败保留选择，完成后刷新当前列表。
- 六种导出按显示列和选中记录输出，排除选择/操作列。保留参考的游戏按钮/状态 HTML 数据，XML 使用 DOM 节点序列化，正确处理特殊字符。
- OSS 恢复 800×600 无遮罩窗口、45px 标题栏、固定底栏和四字段布局。多窗口独立读取，支持拖动、最小化停靠、最大化/还原、最上层 Esc，窄屏停靠换行。读取失败可重试；表单重置、保存错误、重复提交锁、关闭和路由清理均验证。关闭不声称撤销已提交的服务端写入。

## 验证与限制

- `python -m unittest discover -s backend/tests`：76 项通过。新增批量状态原子性、225 条、重复 ID、非法值、角色能力测试；已有 OSS 隔离持久化、权限和主体日期排序通过。
- `verify_agents_parity_browser.py`：50 次模拟列表读取、7 次模拟写入，覆盖 225 条 All/导出、筛选、隐藏列、卡片、失败重试、过期响应、批量状态、权限入口和 OSS 生命周期；1920/1024/390 截图及 320px 双窗口停靠通过。
- `verify_whitelist_parity_browser.py`、`verify_profile_parity_browser.py`、`verify_agent_navigation_scope.py` 通过。22 个 public 根目录 JS 语法检查通过；本次未修改 vendor 文件。
- `audit_pages.py`：12/13。主体通过；设备风控真实接口仍 503，原因是会员入选规则未确认。
- 旧 `verify_whitelist_browser.py` 使用已废弃的 `data-whitelist-id/data-field` 选择器而超时；已使用现行 parity 专项验证。本轮未将该旧脚本的失败冒充通过。旧主体分页/导出脚本同样需按新控件选择器迁移，现行专项为本文件所列脚本。
- OSS 保存只在合成浏览器响应和临时测试数据库验证，未测试参考保存约束或真实对象存储连接。主体新增/编辑表单、删除确认及实际角色映射仍待进一步对照；主体分析地图和统计口径仍待完成。
