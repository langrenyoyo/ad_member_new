# 广告列表浏览器回归

## 请求时序与失败重试

`verify_ads_request_order.py` 在浏览器内暂扣请求并倒序返回，验证旧成功响应不会覆盖新页、旧失败不会写入新页错误提示，以及离开广告页后响应不会写入其他页面。翻页失败现在提供“重试”按钮，重试仍请求失败的页码和原筛选条件，成功后移除错误提示；不再必须借助回首页刷新来恢复。该脚本、分页回归、广告浏览器回归和 JS 语法检查均通过。

## 分页补齐

对照公共 `table-controller.js` 的每页默认 10 条、10/15/20/25/50 选项、记忆条数和跳页配置，补齐原来仅显示总数的广告分页。请求按当前每页条数计算 offset，筛选和重置回首页；记录减少导致页码越界时重新取最后有效页。晚返回响应不能覆盖较新请求或离开广告路由后的页面。

`verify_ads_pagination.py` 使用 35 条浏览器固定记录验证第 4 页最后 5 条、变更每页条数、跳页、空结果、重置、数据缩减与刷新后条数记忆。原有广告工具栏、筛选/导出、浏览器回归及 JS 检查通过。分页视觉和对标实际页级配置仍待双端采集，本地请求回归不代表完整模块一比一。

## 筛选请求一致性修正

代理商选项修复为空白标签及错误提交名称的问题：现在显示名称、提交 ID。广告类型默认值进入状态与初始/重置请求，修复此前界面显示激励但请求未筛选的差异。重建表单恢复已提交字段；选项异步响应仅更新原表单，原表单离开页面后不再写入其他页面。

`python verify_ads_filter_contract.py` 使用固定游戏/代理商及空广告响应，通过名称特殊字符、ID 请求参数、初次及重置默认条件、表单恢复、认证导出参数检查。原有 `verify_ads_browser.py`、`verify_ads_tools.py` 及 `npm run check` 同样通过。这证明本地筛选链路修正，不证明对标后端全部筛选语义或全站一比一。

`verify_ads_browser.py` 已覆盖本地真实登录后的广告列表流程：

- 20 列表头加载
- 筛选请求和空结果状态
- 筛选值保留
- 重置后默认广告类型恢复为激励（`is_fu=0`）
- 导出 CSV

本轮修复了两个实际问题：提交按钮缺少明确的 `type="submit"`，空结果行缺少 `.ads-empty` 状态标记；广告导出改为携带当前 Bearer token 的 `fetch` 下载，避免直接跳转导致 401。

验证：

```text
npm run check
python verify_ads_browser.py
```

两项均通过。该回归证明广告页面的本地交互链路，尚不等价于与对标站同数据的逐像素验收。

## 视图切换修正

保存的 `visual-baseline/reference-verified/table-controller.js` 中 `showToggle:true` 与 `cardView:false` 表明该按钮切换表格/卡片视图。先前实现的紧凑行高不是对应功能，已替换为带字段名称和值的卡片视图。隐藏列同样作用于卡片，刷新保留视图和列选择；重新绑定工具栏时清理旧列菜单，避免重复菜单。

`verify_ads_tools.py` 使用浏览器固定响应检查特殊字符原样显示、卡片字段标签、列隐藏/恢复、刷新后保留卡片及切回表格；该测试已通过。卡片几何与字体仍需同数据双端截图验证，未认定视觉一比一完成。
