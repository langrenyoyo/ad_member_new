# 会员修改金币表单

对标已有只读表单证据 `visual-baseline/reference-verified/member-behavior-forms.json` 显示“可用金币”“冻结金币”两个文本输入及“确定”“重置”。本地原列表仅用 prompt 修改可用金币，无法同时修改冻结金币。

已替换为双字段对话框。打开时读取会员详情并预填当前数值，重置恢复本次读取值；保存一次 PATCH 两个数值，沿用现有后端权限及原子校验。拒绝或失败保留输入并展示错误。保存中禁用重复提交；Escape/关闭按钮取消，路由切换关闭，迟到的加载或保存响应不重新打开或刷新其他页面。

`verify_member_coin_dialog.py` 通过：预填、重置、NaN 阻止提交、两个字段的数值 PATCH、403 后保留输入、成功刷新、取消、重复请求保护及导航后返回。测试写入均为浏览器模拟接口。后端已有 `test_member_coin_form_atomic_validation` 用隔离数据库验证权限、非有限数值、非法输入不部分更新及两字段持久化。

表单目前仅完成字段及交互对齐，未完成对标弹窗尺寸和全部视觉状态的截图验收；不能据此宣称修改金币流程全面一比一。既有修改金币接口也不等同于支付、会计或资金流水全流程验收。

实测外层弹窗为 800×600、标题栏高 45、底部按钮区高 53。两个输入宽约 503.33、高 33，字段间隔 15。已按测量修正本地宽高、深色标题栏、字段位置及底部按钮区，并添加最大化/还原。

`compare_member_coin_fixture.py` 比较相同值、相同尺寸的弹窗区域：差异像素占比 0.6065%，平均 RGB 差异 0.45126。产物已加入汇总报告。`verify_member_coin_dialog.py` 增加最大化及还原尺寸验证，原有保存/失败/取消/导航测试继续通过。

此处仅对比静态默认值状态，尚有标题栏最小化控件、边缘细节及校验状态差异；移动端和最大化后的完整视觉未验收。对标无任何业务写入，不能用静态对比替代实际业务规则核验。

## 最小化补齐

对标最小化实测为左下角 180×45，1920×1080 视口下位置 (0,1035)，点击还原恢复 (560,240) 的 800×600。已实现本地最小化与还原：最小化时转为非模态标题栏，隐藏表单，输入节点保留；还原重新进入模态，不重新读取或丢失编辑值。最终关闭仍清理路由监听和节点。

`verify_member_coin_dialog.py` 增加精确最小化位置/尺寸、隐藏表单、还原尺寸和未保存值保留验证，通过。`compare_member_coin_fixture.py` 新增 180×45 最小化截图和差异图；该小区域差异像素占比 9.6296%，主要控件细节仍待修正。默认弹窗差异像素占比 0.6106%。这两个指标使用不同面积，不能互相替代或用大弹窗空白稀释标题栏差异。

仍需补齐最小化标题栏像素细节，以及从最大化状态再最小化/还原的双端行为和移动端状态；本轮不宣称全部窗口状态已一比一。

## 标题栏与最大化规则实测

读取标题栏计算样式，确认标题字号 14px，三个控件各宽 16px、高 45px、左间距 10px，图标来自对标公开的 iconfont。已保存对应 WOFF 到 `public/assets/fonts/reference-iconfont.woff`，并以独立字体名在金币弹窗中使用，替换普通字符占位；标题和控件间距同步修正。

实际对标最大化后隐藏最小化按钮，无法通过界面直接进行“最大化→最小化”。已按此规则隐藏本地按钮。读取完整窗口状态并保存 `window-states.json`：最大化为 1920×1080，点击还原回到 800×600。浏览器回归增加最大化时最小化按钮不可见断言，通过。

## 前端校验边界核验

新增 `inspect_member_coin_validation.py`。登录并只读打开表单后，拦截所有非 GET/HEAD/OPTIONS 请求，以固定错误响应在浏览器内结束请求，仅记录 coin/freeze_coin 两字段，不记录或导出会话令牌，不向对标服务器提交业务更改。

证据保存在 `visual-baseline/reference-verified/member-coin-dialog/client-validation.json`。对 `abc`、`-5`、`1.25`，对标前端均发起请求，字段值为输入字符串；本轮空值检查未观察到请求。重置从 99/88 恢复事先指定的初始值 12.5/3。这个证据只描述浏览器行为，不能证明服务器接受或拒绝上述数值。

本地前端目前在非数字和非有限数值时直接阻止提交，后端也拒绝该类输入；与对标把非数字交给服务端处理的交互存在差异。此前有限数值测试通过，不等于该规则已与对标一致。缺少对标服务端规则证据时，未取消本地数值校验，也未宣称金币修改业务完全一比一。后续需要对标接口规范或隔离测试环境验证错误响应、数值范围、精度及资金流水规则。

## 标题栏拖动

对标标题栏计算样式为 `cursor:move`。实际鼠标拖动 (100,60) 后弹窗从 (560,240) 移至 (660,300)，最大化再还原返回拖动后位置，记录在 `drag-states.json`；`inspect_member_coin_dialog.py --drag` 可复核。

本地新增普通窗口状态的标题栏指针拖动，按钮操作不触发拖动，最大化和最小化时禁用拖动。位移与窗口状态分离，还原保留拖动位置，输入节点保持不变。指针抬起、取消或丢失捕获时结束拖动；本地将窗口限制在可视范围。

`verify_member_coin_dialog.py` 增加相同鼠标位移及最大化还原坐标断言，通过。该证据覆盖正常桌面视口内拖动；屏幕边缘约束、多次改变视口尺寸和移动端触摸行为尚未与对标逐项验收。
