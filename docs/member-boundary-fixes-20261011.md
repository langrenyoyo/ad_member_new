# 开户、调账精度与删除边界修复

本次修复对应复查报告的三个 P1 问题，未操作生产数据库。

## 行为变化

- 管理端开户接口要求可用余额、冻结余额、累计/月/日收益以及 parent_id 均为零。非零（含负数）返回 422；开户后通过专用调账和邀请绑定/改绑建立业务数据。原先依赖开户表单设置初始金币或上级的调用方必须调整流程。
- 调账目标范围暂定 0–1,000,000,000 金币，最多六位小数；检查目标、原余额及流水差额转为 float 后能否按六位小数还原。不满足要求时拒绝，避免金额校验成功但落库失真。后台提示范围、拒绝超限及超精度输入，并以字符串传输调账金额。
- 删除补齐支付宝绑定、支付订单、刷新会话、微信身份、广告事件/审计、设备检查/准入/最近会员、补贴预留关联。非零余额、冻结或历史收益同样禁止删除；有业务痕迹的账号应停用。未自动删除或清理任何历史关联。

## 限制

这是旧 Float 模型下对管理调账入口的保护，不等于完成全链路 Numeric 迁移；广告累计、提现及历史账务仍需统一精度改造和迁移前后对账。未解决 APP 进程死亡后的补贴提交恢复，未做 PostgreSQL 并发或生产验收。无需新增数据库迁移。

## 验证范围

新增开户资金/邀请拒绝、零余额开户及删除、调账极大值和小数边界、绑定收款账户/刷新会话/余额删除拦截测试。浏览器测试覆盖超上限、超六位小数拦截及字符串金额提交。完整结果见交付说明。

验证结果：后台完整回归 162 项通过（约 98 秒），44 个 JavaScript 文件语法检查通过，调账与改绑浏览器测试通过。本轮未修改 Android 代码，未重新构建 APK。
